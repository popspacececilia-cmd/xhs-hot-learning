# 收件箱与公开信息采集

收件箱目录必须由用户在任务中指定。未指定时先询问，不猜测本地路径，也不在项目内创建替代收件箱。

## 目录

1. 收件箱记录
2. 扫描和去重
3. 灵造采集
4. 链接型视频边界
5. 失败处理

## 收件箱记录

支持 Markdown 或文本记录。典型格式：

```text
### 素材名称
时间：2026年7月12日 15:27
链接：http://xhslink.com/o/xxxx
收藏原因：标题
补充想法：
状态：待处理
```

`状态：已处理` 直接跳过；状态为空、待处理或其他未完成值视为待处理。源文件只允许把对应记录的状态值更新成 `已处理`。

## 扫描和去重

1. 使用 `scripts/inbox_status.py scan` 获取待处理记录。
2. 从目标账号素材库按标准链接和原始链接双重去重。
3. 同一链接已有完整结果时不重复调用灵造；补齐源记录状态即可。
4. 同一链接已有不完整结果时，从缺失步骤继续。
5. 单次处理上限由任务提示指定，默认 10 条。

短链接解析后的标准链接、原始短链接和笔记 ID 都应保留，避免重定向造成重复样本。

## 灵造采集

对每条链接以完整素材底稿为目标，获取实际可见的：

- 标题原文、正文原文、标签、作者、作者 ID、发布时间、内容类型、标准链接和笔记 ID。
- 封面图 URL、图片 URL、IP 属地（如返回）。
- 点赞、收藏、评论、分享等平台数据。
- 视频笔记的完整口播文案 / 语音转写 / 逐字稿；不能只保存总结，摘要只能作为附加层。
- 行动引导：关注、评论、私信、下载、领取资料、跳转、使用工具或其他明确下一步。
- 用户预设排序下的公开评论；默认高赞评论时，记录评论原文、点赞数、回复数、作者回复（如返回）、评论时间。
- 评论里的资料需求、功能需求、疑问、反对、补充、误解、购买意图、下载/求链接意图。

将结果映射到文字层、图片层、视频文本层、数据评论层和来源边界。某字段未返回时保存缺失状态；不能因为底稿要求该字段就推断或补造。

调用前检查版本和连接。版本过期、连接失败或授权异常时停止采集并保留原状态。缺失指标使用 `null` 或缺失标记，不能使用 `0` 伪造。

## 链接型视频边界

只有链接、没有本地视频时：

- 可以分析灵造返回的封面、逐字稿和平台数据。
- 可以把逐字稿划分为内容段落，但不能称为真实镜头分段。
- 没有时间轴时不能声称精确的逐字稿节奏。
- 未获得的视频关键帧、完整画面 OCR、音乐、声音、字幕样式、镜头顺序和真实剪辑节奏全部标记为未获取。

## 失败处理

以下情况不标记已处理：

- 灵造无法返回任何可用内容。
- 底稿或分析保存失败。
- 目标账号工作区写入失败。
- 找不到对应记录或同一 URL 命中多个记录。
- 任务中断或校验失败。

部分采集但足以形成可靠底稿时，可以完成处理；必须保存缺失字段和置信度。
