## 融合边界

Lingzao playbook 是判断增强层，不是主流程。主流程仍由本 skill 负责：

```text
上游素材包 -> 事实底稿 -> 机制分析 -> 账号迁移
-> 候选规则 / 内容机会 -> 目标账号工作区 -> 状态回写
```

不要复制 Lingzao playbook 的完整输出格式来替代本 skill。只吸收其判断问题，并把结论写回本 skill 的证据、机制、迁移、内容机会和生命周期字段。

当 Lingzao skill 和对应 playbook 可用时，优先读取对应 playbook；不可用时，使用本文件的轻量判断清单。

## 对标对象三分类

处理对标账号、博主案例或账号主页素材包时，先分类：

- 主对标：仍在更新，近期有高互动内容，受众/阶段/赛道与目标账号匹配，有可持续内容引擎，能在 7 天内设计低成本测试。
- 案例观察：有启发，但核心资源、阶段、场景、制作能力或账号信任不可直接复制。
- 灵感素材：只值得学习一个标题、封面、结构、评论需求或选题点，不进入长期主对标。

分类结果必须写入账号拆解或样本总览，避免所有素材被同等深拆。

## 对标账号质量门

参考 Lingzao 的 `benchmark-account-discovery-quality-gate` 和 `comparable-account-breakdown-report-template`，但只作为判断门：

1. 账号是否还在更新。
2. 近期是否有高互动作品，而不是只靠历史偶然爆过。
3. 受众、阶段、内容形式和目标账号是否匹配。
4. 爆点靠内容方法，还是靠脸、身份、城市、团队、供应链、成熟账号信任等不可复制资源。
5. 是否有可持续内容引擎，而不是只爆单篇。
6. 目标账号能否在 7 天内做一个低成本测试。

未通过质量门的账号可以保存为案例观察或灵感素材，不应自动进入主对标和深拆队列。

## 账号 / 案例拆解判断

参考 Lingzao 的 `creator-case-general-analysis-framework` 时，优先吸收这些层，不强制每次完整 12 层：

- 表层赛道：明显赛道是什么，赛道标签是否足够解释它。
- 记忆锚点：用户离开后记住人、场景、物、句子还是反差。
- 新叙事：它是否提供一种新的生活、工作、学习、赚钱或内容生产方式。
- 证明系统：它用什么证明自己说的是真的，如过程、结果、评论、场景、作品或身份。
- 用户欲望：用户想获得 shortcut、共鸣、判断、教程、清单、身份确认还是生活方向。
- 内容引擎：故事、教程、研究、清单、互动、转化、日常、地方迁移等是否可持续。
- 评论需求：评论是在求、问、争论、补充，还是只有泛夸。
- 商业入口：广告、产品、课程、社群、咨询、服务或线索是否自然。
- 隐藏资源：不可复制的资源、经验、场景、团队、能力和信任。
- 可学 / 不可学 / 可改造：分别落到账号迁移与内容机会。

## 单篇爆款 10 项判断

参考 Lingzao 的 `single-note-breakdown-workflow`，把 10 项判断吸收到 `03_机制分析/爆款类型与可学层判断.md` 或等价分析文件：

1. 一句话判断：值得学、部分值得学、不建议学，以及原因。
2. 爆款类型：教程、清单、情绪共鸣、身份反差、材料/场景反差、热点改写、产品/引流、评论需求驱动等。
3. 标题为什么有人点：关键词锚点、结果、时间/成本捷径、反差、好奇、身份召唤、痛点/欲望。
4. 封面为什么有人停：视觉主体、封面大字、信息密度、人物/场景/材料反差、构图和一秒理解度。
5. 大纲 / 脚本结构：图文页序、口播 hook-问题-证明-步骤-结尾、Vlog 场景顺序或故事弧。
6. 评论区说明什么：求教程、求链接/工具/清单、共鸣、质疑、补充经验、购买/咨询信号、泛夸。
7. 为什么爆：可复制公式、一次性情绪、平台趋势、大号信任、高制作能力、低粉运营爆点等。
8. 可学点：标题、封面、选题、结构、评论复用、系列化潜力、证明方式等。
9. 不能照抄：脸、身份、年龄、城市、资源、团队、剪辑能力、成熟账号信任、极端经历等。
10. 改成当前账号版本：标题方向、封面文案、图文结构、口播脚本、Vlog 分镜或知识卡片方向。

这 10 项是分析层字段，不是最终沉淀层。是否进入规则、选题池或长期 skill，继续按证据强度、账号适配、用户确认和发布验证判断。

## 标题共同决策

标题不由 Lingzao 或本 skill 单方决定。每个进入测试的标题方向都要保留双判断：

- 本 skill 判断内容支撑：标题从内容里提炼了什么，放大了哪个价值点，正文/逐字稿/证据是否能兑现，属于忠实表达、合理增量、风险增量还是失真。
- Lingzao 判断发布点击：谁会点，关键词锚点是什么，点击理由是什么，是否适配封面，是否过长、过泛、过模板化。
- 用户判断：用户更喜欢哪个，是否像自己，是否敢发，修改原因是什么。
- 发布反馈：实际数据、评论、制作成本、修改成本和下次调整。

输出给用户时不要只给一个最终标题。至少呈现 2-3 个候选标题，并列出点击潜力、内容支撑、风险和适用场景。用户选择与理由要写入标题测试记录。

## 发布前后检查

参考 Lingzao 的 `pre-publish-readiness-check` 时，只做发布前闸门：

- 标题是否有清晰关键词锚点和点击理由。
- 封面是否一秒看懂。
- 前三行 / 前三秒是否承接标题。
- 正文是否兑现标题承诺。
- 是否有过度承诺、洗稿感或与账号语气冲突。
- 是否有明确验证目标。

参考 `post-publish-data-review-workflow` 时，只回填验证结果，不把单次成败永久固化为规则。

## 保存方式

推荐人工可读文件结构：

```text
03_机制分析/
├── 爆款类型与可学层判断.md
├── 标题-封面-开头承接.md
├── 正文脚本结构.md
├── 评论需求与互动机制.md
└── 证据强弱与替代解释.md
04_账号迁移/
├── 可迁移性与制作成本.md
└── 原创迁移建议.md
06_内容机会/
└── 内容机会与标题方向.md
```

内容机会必须使用本 skill 字段保存：

- 来源样本。
- 候选机制。
- 目标用户问题。
- 核心判断。
- 实质区别。
- 原创增量。
- 标题共同决策候选。
- 热点 / 常青价值。
- 适合形式。
- 制作成本。
- 所需素材或证据。
- 风险。
- 待验证策略。

示例：Lingzao 可提出“把杂活吸干核心竞争力改成小常版本”；本 skill 要保存为可验证机会，例如展示“素材收件箱 -> 上游采集 -> 单篇样本 -> 内容机会 -> 选题池”的真实工作流，并记录候选标题、制作成本、风险和评论验证目标。
